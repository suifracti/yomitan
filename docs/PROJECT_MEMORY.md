## L-001 B站多P：有字幕不等于当前选集正确

触发：修改站点字幕发现、选集、URL 解析或来源缓存。

证据：[716e48a](https://github.com/suifracti/yomitan/commit/716e48aefb1e1546216c4f4c8d485ec3012b8df3) 的真实 diff。`bilibiliSources()` 先按 bvid 查询 pagelist；旧实现固定 `pages.data[0].cid`，所以第二 P 仍选第一 P。修复按 URL 的 p（默认1）选对应 cid，再查该 cid 的字幕列表。不是登录状态问题，也不需要重造字幕解析器。

保留：默认第一P与显式第二P要对应正在播放内容；缺 cid 返回无可用来源，不猜内容。B站即使 textTracks 和字幕资源请求为空，仍可能由播放器 DOM 绘字；现行来源链复用 pagelist → 当前 cid 的 wbi/v2 → fetchSubtitle → B站 JSON 解析（25f5f7fb、716e48ae）。字幕文件先匿名请求，失败才带凭据，保留现有下载行为；不要因旧的一次未登录失败就断言登录是唯一根因。

实际结果：[第2P可见面板验收](youtube-study-wiring.md#b-站第-2-p-最后验收2026-10-24gpt-接续)，记录提交 f496f452。2026-10-24 主 Chrome 的 BV1xWnM6HEUU?p=2 列出英语/中文两轨，默认英语 240 句，首句 `Hello my wonderful English learners!`，0:00；该次没有另测中文切轨或保存制卡。2026-11-11 已读该段正文与对应实现，复用其有日期的实机证据，本轮没有重跑。

## L-002 记笔记、选择制卡与真实同步是不同动作

**笔记已写入，扩展本地记录没更新**：在 `StudyJournal.save` 区分本机桥的 `vaultSaved` 和本地问答/关联。已确认的笔记不因浏览器关联写失败变回待保存，批量继续下一个；界面提示后续问答暂不能依赖自动补充。原生保存未回执仍停，不抹掉问答、不重发已经确认的笔记。见[浏览器关联写失败](youtube-study-wiring.md#2026-11-18-笔记写入和浏览器本地关联分别确认)。

**先后打开同句的两个意思，追问应留在原记录**：旧 `sourceKey` 按词、句和出处合并，用作同步关联时后打开的记录覆盖前一条，词卡追问也没带原记录号。现在普通词卡用 `conversationKey` 按有效记录号加原语境分离，没明确打开笔记、也没在当前卡保存时只留本地。确认保存只关联本次交付的轮次；用桥确认的轮次 ID 读旧历史，不把没有归属的旧问答塞给任意义项。受校验字幕和收藏仍用原来源键。见[两条笔记的连续追问](youtube-study-wiring.md#2026-11-18-同词同句的追问按笔记归属)。

**刚升级，旧问答不能混入新同步**：旧 `update:` 项的手动标记也不能证明队列里的所有轮次都是手动选择，旧合并可能夹进自动追问。旧项原样保留，`StudySync.deliver` 不发送；新的 `update:v2:` 不合并旧键。学习库「旧问答需核对」可读、复制，不自动改投；收藏与桥已写入后的卡片核对照常。见[旧队列与当前追问的对照](youtube-study-wiring.md#2026-11-18-升级前未送出的旧问答留给本人核对)。

**词卡里要继续问的是这一条旧笔记，不是最近的一条**：「我的记录」按已读到的记录号列简释、原句与来源，优先本句。按词的近期摘要没召回较早义项时，再查现有本页索引；不把同页另一个原句冒充本句。继续学习只传编号与语言，打开后沿 `readStudyRecord` 重读；原笔记链接和 Anki 仍是各自的入口。见[从词卡选择这条笔记](youtube-study-wiring.md#2026-11-18-从我的记录继续问指定的笔记)。

**已保存的两个义项不能共用一枚弹窗标签**：旧标签身份只看词、原句、网址和视频位置，切回会恢复第一条笔记和草稿。现在标签、词卡和记录页都从 `savedStudyRecordId` 取明确身份，标签加短义。捕获草稿不再把 DOM 中自动匹配的候选笔记当作恢复对象；只有当前同来源的明确保存回执才刷新该标签的笔记、词义和轮次。正常词卡与受校验字幕不互相套用授权。见[两条草稿的切换验证](youtube-study-wiring.md#2026-11-18-收起词卡后不同义项各自保留草稿)。

依据：既有 Vault 阶段反馈和当前项目保护约定。笔记保存不能隐式覆盖用户手工卡片或复习排程；同词不同原句/来源不能误归属。临时 Vault/FakeAnki、模拟字幕与真实 Profile 分层记录，图片或视频网址不能代替原声音频证据。

**记得「避风港」，想找回当时那句话**：学习库的 `libraryList` 在原有学习索引里先按分类和线索过滤，再每十条分页。空格连接的线索必须同属一条记录，词头或原形全字匹配、连续短语优先；结果保留原记录号、原句和来源时间。不要对整个记录做 JSON 字符串匹配，也不要为搜索逐条核对 Anki。旧桥只筛已读页；仅在浏览器的收藏仍可在「收藏」里找。见[临时库验证](youtube-study-wiring.md#2026-11-18-用中文意思或几段线索找回旧原句)。

下次：先查当前产品规格和保存链，而不是重新增加一个同步系统。保留具体版本、对象 ID 与冲突/删除语义；缺真实证据写未知。此前仅为要求与历史证据边界，2026-11-11以下新增临时链证据不代表正式库通过。

“只在Anki／重建笔记／恢复后记录消失”：orphan_action 原先每次无条件追加同一张卡，若上次回复丢失而缓存孤卡行仍在，再点恢复会重复同一card ID；同步区拒读重复卡，增量索引因此看不到刚恢复的记录。现按noteId保留单一关联，重试不重复追加；卡型用原有 study_kind:: 标签，保留原来无标签时的语境卡行为，不把所有新恢复卡硬写成context。test_study_repair原有连贯场景扩展了重复恢复与meaning卡型断言，两个缺口均先失败再通过，且确认无Anki写入/删除/移动/排程。复用旧库和标签，没有新增协议、配置或同步器；对应交接“2026-11-11 重建笔记的重试与原卡型”。

**重建出了“听原声，拼写这个词。”这个词**：英语卡的 Word 是可编辑题目。新卡在原 Source 链接里另留实际原词；旧卡可核原词文档或原卡的编号。这里只解析链接文字、不打开它。用原来明确记录的视频秒数，不从分享网址猜；无法核出词时让学习者补一次。普通记录能对回原来的笔记/卡号，重复确认不新制卡。这不能从 Anki 还原未曾存进去的问答、音频附件或受保护的字幕身份。见[两个时间点的恢复实测](youtube-study-wiring.md#2026-11-18-从-anki-找回的是原词而不是题目)。

**重建错放到刚选的文件夹；再点一次抹掉我补的解释**：从卡片的原笔记链接匹配已配置的位置，新卡还记原目的地编号。旧链接最多证明文件夹，不能证明历史牌组选项。没有唯一位置时让人看清当前路径再点重建；旧卡的路径不是读写许可。用既有关联编号判断已经处理的请求，不能为了重试再走一次“保存卡片内容覆盖笔记”。英语列表不接收日语学习卡。见[换目录与重复恢复](youtube-study-wiring.md#2026-11-18-重建回原文件夹保留后来的手写解释)。

**原词、原句都一样，但当时选了不同意思**：新卡保留实际选定的 `entry.sense` 和已有的 lemma。重建不是“又发现了新意思”，不能重新分配 #2/#3，也不能把两张卡按同一行英文合并。原记录标记只与重新算出的编号比较，不用它打开别处的笔记。没有留下义项的旧卡，无法证明同属已有笔记时保持待处理。见[两种 charge 的恢复](youtube-study-wiring.md#2026-11-18-同一句话里的两个意思分别找回)。

“卡已恢复却一直提示被删除”：自动同步原先只在记录还不是missing时比较ID是否消失；处于missing的记录即使同一Anki ID重新出现也不会核对，且mod未变时edited:1无法补触发。现复用每轮已有的带学习标签ID清单，关联ID缺失状态与记录missing状态不一致时才reconcile；恢复后安静轮次不再重复核对。新增临时删除→同ID/同mod返回→清除missing→安静一轮用例通过，原2000卡notesInfo只读当日编辑与候选用例也通过。没有实测Anki撤销按钮，不把替身情景冒充正式库行为；未新增扫描或改变排程。

“点需处理没反应／切分类后空白”：学习库loadPage在loading时直接return，分类按钮先改category，因此前一次列表慢响应时会丢失新分类查询。现仅记住一个待刷新请求，旧列表返回后不提交过期快照，完成后读取当前所选分类；不加计时器或并发拉取。study-library-page.test.js新增慢列表期间切pending的DOM场景通过，原收藏/同步/冲突选择场景也通过；旧用例最初把已有ankiToday调用算进固定四次流程，现只从该断言排除今日条，保留原四步与载荷断言。JS及测试lint均0，未实测Chrome。

**听音练习的题目是声音，不是题面文字（2026-11-18）**。若两个语境都用“听原声，拼写这个词。”考 just，纯文本的学习点指纹会相同，旧桥会返回已同步，却让第二条也关联第一张卡和第一段音频。新建听原声→意思、视频声音字幕、听音拼写卡时只认这条记录自己的卡片标签；不拿题面/答案查重替代对录音的选择。丢回执仍用原标签找回，不重复送卡。文字卡仍可跨例句关联同一学习点；不批量改过去的关联、媒体、模板或排程。复现与边界见[原声卡记录](youtube-study-wiring.md#2026-11-18-相同题面不同原声的听写卡)。

**制卡回执**：原生端 `study_cards.card_progress` 从实际卡片回执计算张数及已到达的阶段，不把这些派生数写回学习数据。词卡/学习库用 `study-data.cardReceipt` 显示，旧桥快照仍可读，视频栏与学习小结取同一计数；“未确认”不能写成“Anki 没有这张卡”。两张卡有一张回执丢失时，应同时看到一张已确认、一张未确认；重新确认只送既有记录 ID，不重写笔记或生成草稿。若连本批题面和答案被笔记接受的回执都没有，保留编辑框。旧 ID 仍可用于打开卡，不拿它冒充刚刚核实的送卡结果。已知已删除或关联不明的那张不计数，其他有回执的保留，视频栏提示去学习库处理。未核对不代表从未制卡，不另推荐同句。见[中断补交](youtube-study-wiring.md#2026-11-18-词卡与学习库使用同一份制卡回执)和[视频词表回执](youtube-study-wiring.md#2026-11-18-视频词表和学习小结也按制卡回执计数)。

## L-006 网页视频继续学习：读回轨道、恢复入口和状态合并必须一起接上

## L-007 视频已记词退回制卡：恢复原记录，而不是只带词和句子

**来源链接和记录编号不是同一回事。** 改视频分组键时看 `study_sources.py`（浏览器站点表由同一文件生成）；不能因此改 `entry_id` 或归档笔记的编号。没有实际播放时间就保留原链接：曾将分享地址的 83 秒写成 0 秒，也会把普通页面的章节锚点丢掉。只有确实知道时间，才为 YouTube/B站生成跳时链接；普通网页不加时间参数，本地文件在来源行只显示文件名。见[临时笔记复现](youtube-study-wiring.md#2026-11-18-来源链接不再从零秒开始)。

**在原网页找回本页笔记**：「本页生词」的入口只让后台按顶层消息来源打开学习库，不把笔记结果返回网页。学习库用原有 `source` 分类和分页只读索引；同文的章节或文本定位不分组，查询参数、哈希路由仍分开。不动原 URL、记录号或制卡来源。见[12 条的浏览器往返](youtube-study-wiring.md#2026-11-18-从本页生词找回这篇文章的原句)。

**翻译是对照，不是原文的一部分**：整页及下方单句译文虽然没有改原 DOM，插入的 `.study-page-translation` 仍会被句子扫描走进，抢走真正邻句。原文扫描跳过这个生成的节点，不增换行，保留原句和选词位置；不按语言把网页原生中文段落删掉。见[开译文前后对照](youtube-study-wiring.md#2026-11-18-打开网页译文不再把邻句换成中文)。

## L-012 词形可以共用学习状态，同拼写不一定是同一个词

只在已保存记录明确给出词典原形时，共用该词的义项、网页标色和手动「认识了」；不从拼写猜。一条成熟的 charge「收费」和一条刚保存的 charges「指控」，两种词形都应看到两个意思，撤销后都回到部分掌握。认识 see 不等于认识名词 saw，认识 run 也不等于认识搭配 run into。搭配沿用自己的拼写和关联原词，整句不参与。

**用自己的旧原句辨词义**：学习库首页搜索同一原形或已关联的词形时，用 `study_senses.practice_pair` 从已索引的两种明确义项各取一句。保留实际词形、原记录号和来源秒数；同一原句若存过不同读法，只照常列出，不出二选一。选完展示当时记的意思，不把一次选择当成会了或不会，也不调用模型。旧桥不提供这对练习时无入口。见[两种 charge 的浏览器练习](youtube-study-wiring.md#2026-11-18-用自己的旧原句辨词义)。
